# 阶段5-用户端-外卖交易闭环 前端页面与接口对接

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 页面清单

- 用户端：外卖首页、搜索结果、店铺详情、商品规格弹窗、购物车、确认订单、支付收银台、支付结果、外卖订单列表、订单详情、轨迹页、取消订单弹窗、评价页、售后申请入口。
- 商家 Android/iOS APP：新订单推送占位和订单详情只读联调。
- 骑手 Android/iOS APP：配送任务只读联调。
- 平台 Web：外卖订单列表、详情、日志。

## 接口对接总则

统一前缀：用户端 `/api/v1/c/**`，商家端 `/api/v1/m/**`，骑手端 `/api/v1/r/**`，平台 Web `/api/v1/admin/**`，公开 `/api/v1/pub/**`，第三方回调 `/api/v1/callback/**`。各端仅使用对应 Token：用户端只用 `Customer-Token`，商家 Android/iOS APP 只用 `Merchant-Token`，骑手 Android/iOS APP 只用 `Rider-Token`，平台 Web 只用 `Admin-Token`。

- 页面不得散写 URL，必须通过 API 常量或接口模块调用。
- 每个页面必须处理 loading、空状态、异常状态、token 失效、防重复提交。
- 状态展示必须引用后端枚举，不允许通过中文文案判断业务状态。
- 金额字段以后端分为单位返回，前端只做格式化展示。
- 所有前端写操作必须有按钮禁用和失败重试提示。

## 页面到接口映射

| 页面 | 接口 | 调用端 | Token | 关键响应 |
|---|---|---|---|---|
| 外卖首页 | GET /api/v1/c/food/home | 用户端 | Customer-Token 可选 | banners、categories、activityEntries、recommendedStores |
| 外卖首页/搜索结果 | GET /api/v1/c/food/stores | 用户端 | Customer-Token 可选 | storeId、name、distance、sales、rating、deliveryFee、minOrderAmount、businessStatus |
| 店铺详情 | GET /api/v1/c/food/stores/{storeId}/products | 用户端 | Customer-Token 可选 | categories、products、skus、stock、saleStatus、specs |
| 商品规格弹窗/购物车 | POST /api/v1/c/food/cart/items | 用户端 | Customer-Token | cartId、items、goodsAmount、deliveryFee、discountAmount |
| 确认订单页 | POST /api/v1/c/food/orders/preview | 用户端 | Customer-Token | goodsAmount、deliveryFee、discountAmount、payableAmount、estimatedDeliveryTime、unavailableReason |
| 确认订单页 | POST /api/v1/c/food/orders | 用户端 | Customer-Token | orderId、orderNo、payOrderId、payableAmount、expireAt |
| 支付收银台 | POST /api/v1/c/payments/prepay | 用户端 | Customer-Token | payOrderId、payParams、expireAt |
| 订单详情 | GET /api/v1/c/food/orders/{orderId} | 用户端 | Customer-Token | orderStatus、payStatus、store、items、rider、timeline、actions |
| 轨迹页 | GET /api/v1/c/food/orders/{orderId}/track | 用户端 | Customer-Token | riderLocation、route、trackPoints、eta |

## 前端接口问题审查清单

- [ ] 页面是否有接口来源，不允许只做静态页面。
- [ ] 请求字段是否与后端 DTO 一致。
- [ ] 响应字段是否与后端 VO 一致。
- [ ] 状态枚举是否引用后端权威枚举。
- [ ] 错误码是否有明确用户提示。
- [ ] 分页、筛选、排序是否与接口一致。
- [ ] 支付、接单、抢单、退款、提现是否做防重复点击。
- [ ] 实时消息、轨迹、推送是否有刷新策略。
- [ ] 第三方失败时是否展示可理解提示并允许重试。
