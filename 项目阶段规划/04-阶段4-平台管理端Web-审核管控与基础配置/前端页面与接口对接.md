# 阶段4-平台管理端Web-审核管控与基础配置 前端页面与接口对接

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 页面清单

- 平台 Web：登录、首页、用户列表/详情、商家审核/详情、骑手审核/详情、城市站点、外卖类目、跑腿类目、角色权限、菜单权限、第三方配置、系统参数、操作日志。

## 接口对接总则

统一前缀：用户端 `/api/v1/c/**`，商家端 `/api/v1/m/**`，骑手端 `/api/v1/r/**`，平台 Web `/api/v1/admin/**`，公开 `/api/v1/pub/**`，第三方回调 `/api/v1/callback/**`。各端仅使用对应 Token：用户端只用 `Customer-Token`，商家 Android/iOS APP 只用 `Merchant-Token`，骑手 Android/iOS APP 只用 `Rider-Token`，平台 Web 只用 `Admin-Token`。

- 页面不得散写 URL，必须通过 API 常量或接口模块调用。
- 每个页面必须处理 loading、空状态、异常状态、token 失效、防重复提交。
- 状态展示必须引用后端枚举，不允许通过中文文案判断业务状态。
- 金额字段以后端分为单位返回，前端只做格式化展示。
- 所有前端写操作必须有按钮禁用和失败重试提示。

## 页面到接口映射

| 页面 | 接口 | 调用端 | Token | 关键响应 |
|---|---|---|---|---|
| 后台登录页 | POST /api/v1/admin/auth/login | 平台 Web | 无 | adminToken、menus、permissions |
| 用户管理 | GET /api/v1/admin/customers | 平台 Web | Admin-Token | 分页用户列表、脱敏手机号、实名状态 |
| 商家审核 | GET /api/v1/admin/merchants/applications | 平台 Web | Admin-Token | 申请列表、资质摘要、提交时间 |
| 骑手审核 | GET /api/v1/admin/riders/applications | 平台 Web | Admin-Token | 申请列表、证件摘要、服务区域 |
| 城市站点 | POST /api/v1/admin/cities | 平台 Web | Admin-Token | cityId、updatedAt |
| 第三方配置 | PATCH /api/v1/admin/integrations/{provider} | 平台 Web | Admin-Token | provider、enabled、updatedAt |

## 前端接口问题审查清单

- [ ] 页面是否有接口来源，不允许只做静态页面。
- [ ] 请求字段是否与后端 DTO 一致。
- [ ] 响应字段是否与后端 VO 一致。
- [ ] 状态枚举是否引用后端权威枚举。
- [ ] 错误码是否有明确用户提示。
- [ ] 分页、筛选、排序是否与接口一致。
- [ ] 支付、接单、抢单、退款、提现是否做防重复点击。
- [ ] 实时消息、轨迹、推送是否有刷新策略。
- [ ] 第三方失败时是否展示可理解提示并允许重试。
