# 阶段8-骑手端APP-调度轨迹收益考核 前端页面与接口对接

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 页面清单

- 骑手 Android/iOS APP：工作台、派单弹窗、接单大厅、当前任务、外卖取货页、跑腿取件核验页、导航页、配送页、送达确认、异常报备、收益中心、提现、提现记录、考核中心、违规记录。
- 用户端：轨迹页。
- 平台 Web：调度监控、轨迹回放。

## 接口对接总则

统一前缀：用户端 `/api/v1/c/**`，商家端 `/api/v1/m/**`，骑手端 `/api/v1/r/**`，平台 Web `/api/v1/admin/**`，公开 `/api/v1/pub/**`，第三方回调 `/api/v1/callback/**`。各端仅使用对应 Token：用户端只用 `Customer-Token`，商家 Android/iOS APP 只用 `Merchant-Token`，骑手 Android/iOS APP 只用 `Rider-Token`，平台 Web 只用 `Admin-Token`。

- 页面不得散写 URL，必须通过 API 常量或接口模块调用。
- 每个页面必须处理 loading、空状态、异常状态、token 失效、防重复提交。
- 状态展示必须引用后端枚举，不允许通过中文文案判断业务状态。
- 金额字段以后端分为单位返回，前端只做格式化展示。
- 所有前端写操作必须有按钮禁用和失败重试提示。

| 导航到店/取货点 | POST /api/v1/r/tasks/{taskId}/arrive-pickup | 骑手 Android/iOS APP | Rider-Token | taskId、status、arrivedAt |
| 取货确认页 | POST /api/v1/r/tasks/{taskId}/pickup | 骑手 Android/iOS APP | Rider-Token | taskId、status、pickedUpAt |
| 送达确认页 | POST /api/v1/r/tasks/{taskId}/delivered | 骑手 Android/iOS APP | Rider-Token | taskId、status、deliveredAt |
| 异常报备页 | POST /api/v1/r/tasks/{taskId}/exception | 骑手 Android/iOS APP | Rider-Token | exceptionId、status、platformHandleRequired |

| 提现页 | POST /api/v1/r/withdrawals | 骑手 Android/iOS APP | Rider-Token | withdrawalId、status |

## 前端接口问题审查清单

- [ ] 页面是否有接口来源，不允许只做静态页面。
- [ ] 请求字段是否与后端 DTO 一致。
- [ ] 响应字段是否与后端 VO 一致。
- [ ] 状态枚举是否引用后端权威枚举。
- [ ] 错误码是否有明确用户提示。
- [ ] 分页、筛选、排序是否与接口一致。
- [ ] 支付、接单、抢单、退款、提现是否做防重复点击。
- [ ] 实时消息、轨迹、推送是否有刷新策略。
- [ ] 第三方失败时是否展示可理解提示并允许重试。
