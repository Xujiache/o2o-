# 多 Agent 讨论纪要

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 参与 Agent

- 端侧阶段重构 Agent：建议改为初始化、按端建设、联调、性能安全、全量冒烟的 13 阶段结构。
- 接口契约 Agent：确定 API 前缀、Token、响应结构、接口字段、状态枚举、幂等、审计、第三方回调要求。
- 手测审查模板 Agent：确定每阶段必须有 `手动审查与测试.md`，并包含接口审查、四端联动、第三方联调和多 Agent 复核。
- 文档质量标准 Agent：确定目录命名、文件命名、文档深度、按端组织和反空泛规则。

## 决策

- 删除旧阶段规划，按新规范重写。
- 第一阶段为 `阶段0-项目初始化与全局契约`。
- 最后一阶段为 `阶段12-全量冒烟测试与上线验收`。
- 每个阶段固定 10 个文档。
- 前端文档必须直接包含对接接口问题，不允许只写页面。
- 审查文档必须包含接口审查清单，便于后续人工复核。
