# 阶段0-项目初始化与全局契约 按端实施范围

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 用户端：微信小程序 / Android APP / iOS APP

- 建立用户端小程序 / Android APP / iOS APP 的目录、环境变量、请求封装、Customer-Token 存储规则。
- 建立统一错误提示、登录态失效跳转、地图组件、文件上传组件、状态标签组件。

## 商家端：Android APP / iOS APP

- 建立商家 Android/iOS APP 工程、请求封装、Merchant-Token 存储规则。
- 冻结商家端只存在 APP 的端口边界，文档和路由禁止出现商家 Web/小程序。

## 骑手端：Android APP / iOS APP

- 建立骑手 Android/iOS APP 工程、请求封装、Rider-Token 存储规则。
- 预留定位、轨迹上报、推送设备绑定、后台保活能力。

## 平台管理端：Web 后台

- 建立平台 Web 工程、路由权限、Admin-Token 存储、菜单权限、按钮权限。
- 预留操作日志、第三方配置、系统参数、角色权限页面。

## 端间数据流

- 用户端产生订单、支付、售后、评价和地址数据。
- 商家端只处理外卖相关店铺、商品、订单、售后、营收数据。
- 骑手端处理外卖配送任务和跑腿任务，不处理商家经营数据。
- 平台 Web 只做审核、配置、调度、仲裁、数据和风控，不替代商家 Android/iOS APP 的经营动作。

## 边界审查点

- [ ] 商家端没有 Web 后台规划。
- [ ] 商家端没有小程序规划。
- [ ] 跑腿订单没有进入商家端处理流程。
- [ ] 平台 Web 没有替代商家接单、商品维护、商家日常经营。
- [ ] 用户端、商家端、骑手端、平台端 Token 和权限隔离。
