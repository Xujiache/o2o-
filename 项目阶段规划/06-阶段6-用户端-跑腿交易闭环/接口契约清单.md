# 阶段6-用户端-跑腿交易闭环 接口契约清单

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 全局接口规范

统一前缀：用户端 `/api/v1/c/**`，商家端 `/api/v1/m/**`，骑手端 `/api/v1/r/**`，平台 Web `/api/v1/admin/**`，公开 `/api/v1/pub/**`，第三方回调 `/api/v1/callback/**`。各端仅使用对应 Token：用户端只用 `Customer-Token`，商家 Android/iOS APP 只用 `Merchant-Token`，骑手 Android/iOS APP 只用 `Rider-Token`，平台 Web 只用 `Admin-Token`。

## 本阶段接口详情

### GET /api/v1/c/errand/service-types

- 接口名称：跑腿类型配置
- 调用端：用户端
- 鉴权 Token：Customer-Token 可选
- 权限点：`customer:self`，用户只能访问本人数据；订单、支付、售后等状态变更还需满足当前业务状态。
- 使用页面/场景：跑腿首页
- 请求字段：cityCode
- 响应字段：typeCode、name、requiredFields、enabled
- 状态/枚举：以后端阶段状态机枚举为准，前端不得硬编码中文状态。
- 错误码：`INVALID_PARAM`、`UNAUTHORIZED`、`FORBIDDEN`、`DATA_NOT_FOUND`、`STATUS_INVALID`、`DUPLICATE_REQUEST`、`THIRD_PARTY_ERROR`
- 幂等要求：写操作必须支持 `Idempotency-Key`；重复请求返回同一业务结果，不重复扣款、不重复写业务变更。
- 审计日志：记录 traceId、operatorType、operatorId、targetType、targetId、beforeStatus、afterStatus、ip、deviceId、createdAt。
- 前端对接注意：页面必须处理 loading、空状态、错误提示、防重复点击和 token 过期跳转。

## 接口审查清单

- [ ] 每个接口有调用端、Token、权限点。
- [ ] 每个接口有请求字段、响应字段、字段单位。
- [ ] 每个接口有错误码和前端展示策略。
- [ ] 每个写接口有幂等规则。
- [ ] 每个关键写接口有审计日志。
- [ ] 每个状态变更接口写明 beforeStatus 和 afterStatus。
- [ ] 每个接口能反查前端页面。
- [ ] 每个前端页面能反查接口。
- [ ] 第三方回调有验签、去重、防重放。
