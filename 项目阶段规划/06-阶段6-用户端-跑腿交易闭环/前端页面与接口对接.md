# 阶段6-用户端-跑腿交易闭环 前端页面与接口对接

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 页面清单

- 用户端：跑腿首页、代买表单、代送表单、代办表单、自定义需求页、地址选择、图片上传、报价页、支付页、跑腿订单列表、订单详情、轨迹页、加急弹窗、补充备注、售后入口。
- 骑手 Android/iOS APP：跑腿任务卡片联调。
- 平台 Web：跑腿订单列表、计价规则、违禁品配置。

## 接口对接总则

统一前缀：用户端 `/api/v1/c/**`，商家端 `/api/v1/m/**`，骑手端 `/api/v1/r/**`，平台 Web `/api/v1/admin/**`，公开 `/api/v1/pub/**`，第三方回调 `/api/v1/callback/**`。各端仅使用对应 Token：用户端只用 `Customer-Token`，商家 Android/iOS APP 只用 `Merchant-Token`，骑手 Android/iOS APP 只用 `Rider-Token`，平台 Web 只用 `Admin-Token`。

- 页面不得散写 URL，必须通过 API 常量或接口模块调用。
- 每个页面必须处理 loading、空状态、异常状态、token 失效、防重复提交。
- 状态展示必须引用后端枚举，不允许通过中文文案判断业务状态。
- 金额字段以后端分为单位返回，前端只做格式化展示。
- 所有前端写操作必须有按钮禁用和失败重试提示。

## 页面到接口映射

| 页面 | 接口 | 调用端 | Token | 关键响应 |
|---|---|---|---|---|
| 跑腿首页 | GET /api/v1/c/errand/service-types | 用户端 | Customer-Token 可选 | typeCode、name、requiredFields、enabled |
| 跑腿报价页 | POST /api/v1/c/errand/quotes | 用户端 | Customer-Token | quoteId、baseFee、distanceFee、urgentFee、payableAmount、expireAt、prohibitedWarnings |
| 报价确认页 | POST /api/v1/c/errand/orders | 用户端 | Customer-Token | orderId、orderNo、payOrderId、status、expireAt |
| 跑腿订单详情 | GET /api/v1/c/errand/orders/{orderId} | 用户端 | Customer-Token | orderStatus、priceDetail、pickup、delivery、rider、timeline、actions |
| 加急弹窗 | POST /api/v1/c/errand/orders/{orderId}/urgent | 用户端 | Customer-Token | orderId、urgentFee、status |
| 补充备注弹窗 | PATCH /api/v1/c/errand/orders/{orderId}/remark | 用户端 | Customer-Token | orderId、latestRemark、updatedAt |
| 轨迹页 | GET /api/v1/c/errand/orders/{orderId}/track | 用户端 | Customer-Token | riderLocation、route、trackPoints、eta |

## 前端接口问题审查清单

- [ ] 页面是否有接口来源，不允许只做静态页面。
- [ ] 请求字段是否与后端 DTO 一致。
- [ ] 响应字段是否与后端 VO 一致。
- [ ] 状态枚举是否引用后端权威枚举。
- [ ] 错误码是否有明确用户提示。
- [ ] 分页、筛选、排序是否与接口一致。
- [ ] 支付、接单、抢单、退款、提现是否做防重复点击。
- [ ] 实时消息、轨迹、推送是否有刷新策略。
- [ ] 第三方失败时是否展示可理解提示并允许重试。
