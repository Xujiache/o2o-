# O2O 外卖+跑腿系统按端阶段规划总览

> 商家端仅 Android APP / iOS APP，禁止规划商家 Web 后台、商家小程序。外卖订单与跑腿订单必须独立订单体系、独立状态机、独立计价、独立退款规则。

## 本次重写原则

- 旧规划已删除并按新规范重建。
- 阶段按端组织：先初始化项目，再按用户端、商家端 APP、骑手端 APP、平台 Web 分阶段建设，再进入四端联调、性能安全验收，最后进行全量冒烟测试。
- 每个阶段文件夹都包含完整的 `手动审查与测试.md`，用于人工手动触发审查和测试。
- 所有前端页面文档必须写清楚对接接口、请求字段、响应字段、状态枚举、错误码、异常处理和验收标准。
- 所有接口必须写清楚调用端、Token、权限、幂等、审计、状态流转和测试用例。

## 阶段目录

- `00-阶段0-项目初始化与全局契约`：初始化仓库、工程、环境、模块边界、接口契约、状态机、权限、安全、审计和第三方适配。
- `01-阶段1-用户端-账号地址与基础框架`：完成用户端小程序、Android APP、iOS APP 的账号、实名、地址、定位、个人中心和基础资产入口。
- `02-阶段2-商家端APP-入驻店铺与商品管理`：完成商家 Android/iOS APP 的入驻、审核状态、店铺设置、商品分类、商品、库存和基础营销配置。
- `03-阶段3-骑手端APP-入驻接单与配送基础`：完成骑手 Android/iOS APP 的入驻认证、审核状态、上线下线、接单大厅、基础任务查看和定位上报。
- `04-阶段4-平台管理端Web-审核管控与基础配置`：完成平台管理端 Web 的用户、商家、骑手审核管控，城市、类目、权限、第三方配置和操作日志。
- `05-阶段5-用户端-外卖交易闭环`：完成用户端小程序/Android/iOS 的外卖首页、店铺商品、购物车、下单、支付、订单、轨迹、评价和售后入口。
- `06-阶段6-用户端-跑腿交易闭环`：完成用户端小程序/Android/iOS 的跑腿入口、四类跑腿表单、报价、支付、订单、轨迹、加急、备注和售后入口。
- `07-阶段7-商家端APP-订单售后结算数据`：完成商家 Android/iOS APP 外卖订单履约、售后处理、经营数据、营收结算和提现。
- `08-阶段8-骑手端APP-调度轨迹收益考核`：完成骑手 Android/iOS APP 的智能派单、抢单、履约、轨迹上报、异常报备、收益、提现和考核。
- `09-阶段9-平台管理端Web-调度售后运营财务`：完成平台管理 Web 的全量订单、智能调度、售后仲裁、运营营销、费率财务、数据大屏和导出。
- `10-阶段10-四端联调-接口状态消息资金`：将四端、后端和第三方进行全链路联调，重点验证接口契约、状态同步、消息推送和资金链路。
- `11-阶段11-性能安全兼容与数据验收`：验证性能、安全、兼容、数据持久化、日志审计、备份恢复、报表导出和容量指标。
- `12-阶段12-全量冒烟测试与上线验收`：最后阶段只做全量冒烟测试、接口契约审查、上线前阻断问题清零和上线验收，不再新增任何功能。
